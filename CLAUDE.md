# 1Candbox (онлайн-компилятор 1С): контекст проекта

Сводка предыдущего обсуждения в Claude (claude.ai), чтобы продолжить работу в Claude Code. Положите этот файл в корень папки `onescript-sandbox/`: Claude Code прочитает его автоматически.

## Цель

Сделать сайт, где можно быстро проверить алгоритм на языке 1С (BSL), как на https://www.online-python.com/: вставил код, нажал «Запустить», увидел вывод. Идея появилась после «Цифрового диктанта по 1С», когда для такой проверки не нашлось готового ресурса.

Главное ограничение языка: код 1С обычно привязан к конфигурации и базе данных (справочники, документы, запросы, формы, `&НаСервере`). Без платформы 1С с информационной базой его не запустить. Поэтому песочница проверяет **алгоритмическую часть** языка: переменные, процедуры и функции, циклы, строки, числа, даты, Массив, Структура, Соответствие, ТаблицаЗначений, исключения.

## Что выяснили про рынок

Готового онлайн-компилятора 1С в формате «вставил и запустил» нет. Ближайшие аналоги:
- **Stepik «1С: Практический тренажёр»**: 234 задачи с автопроверкой, 1 290 ₽. Люди готовы платить за практику.
- **1Craft[Code]** (Инфостарт): задачи на язык и запросы. Не больше 30 гостей одновременно, похоже, работает на настоящей платформе с лицензиями.
- **«Турниры 1С»** (xexod.ru): соревнования, выглядит заброшенным.
- **Let's code**: устанавливаемая конфигурация, проверяет решения через OneScript.
- **yaxunit-editor**: редактор в браузере без запуска кода. **BSL Language Server**: статический анализ без исполнения.
- **1С:Элемент**: облачная песочница фирмы 1С, но там другой, статически типизированный язык.

Вывод: ниша свободная, но узкая. Как пет-проект и бесплатная точка входа (потом задачник, тренажёр к экзаменам, проверка кандидатов) проект осмысленный.

## Рассмотренные варианты движка

**A. OneScript** (выбран). Открытая реализация языка 1С на C#/.NET, лицензия MPL-2.0, https://github.com/EvilBeaver/OneScript. Лицензионных вопросов нет. Не умеет запросы, метаданные и формы, есть мелкие отличия от платформы.

**B. Настоящая платформа 1С** (отложен). Схема:
- автономный сервер `ibsrv` (работает без лицензии на сервер 1С);
- файловая база с «песочной» конфигурацией и демо-данными;
- HTTP-сервис, который выполняет `УстановитьБезопасныйРежим(Истина)`, затем `Выполнить(Код)` внутри транзакции с откатом.

Подводные камни:
- через `Выполнить()` нельзя объявлять процедуры и функции;
- `/Execute` не исполняет модуль внешней обработки;
- `DESIGNER` на Linux без графики требует Xvfb;
- нужен сторожевой процесс от бесконечных циклов и пул «тёплых» контейнеров.

Лицензии: бесплатная community-лицензия подходит только для разработки и обучения (до 3 клиентских сеансов, 1 веб-сеанс, до 3 активаций на учётную запись). Для публичного сервиса нужно согласование с 1С: договор «Аренда ПО 1С» и/или купленные лицензии. Вариант B имеет смысл как будущий режим «с запросами» за тем же интерфейсом «код → JSON».

## Принятое решение: OneScript в браузере через WebAssembly

По образцу online-python (Pyodide, то есть CPython в WebAssembly). Сервера для выполнения кода нет, сайт полностью статический.

### Стек

- **Движок:** OneScript 2.0 (C#), исходники клонируются с GitHub, применяются правки.
- **Обвязка:** C# / .NET 8, SDK `Microsoft.NET.Sdk.WebAssembly`, RID `browser-wasm`, Mono-интерпретатор без AOT, `PublishTrimmed=false` (OneScript находит объекты через рефлексию).
- **Связь с JS:** `[JSExport]` в `Runner.Run(code, input)`, которая возвращает JSON.
- **Фоновый поток:** Web Worker (ES-модуль) загружает `_framework/dotnet.js`.
- **Редактор:** CodeMirror 6 и `@1c-syntax/codemirror-lang-bsl` (MIT).
- **Страница:** HTML + CSS + JavaScript без фреймворков, светлая и тёмная тема, шрифты IBM Plex Sans и JetBrains Mono.
- **Сборка:** esbuild для фронтенда, `build.sh` для проекта целиком. Хостинг: любой статический сервер.

### Архитектура и поток выполнения

```
app.js (основной поток) ── postMessage {run, code, input} ──► worker.js
   ▲  таймер 8 с: worker.terminate() + новый воркер                │
   └──────────── postMessage {result | ready | fatal} ◄────────────┘
worker.js: dotnet.withApplicationCulture('ru-RU').create()
           → getAssemblyExports('OneScriptWasm.dll') → Runner.Run(code, input)
```

На каждый запуск `Runner.RunToJson`:
1. ставит культуру `ru-RU`;
2. собирает новый движок: `DefaultEngineBuilder` → `SetDefaultOptions` → `UseImports` → `UseBinaryDataOptions` → `UseBackgroundTasksOptions` → `UseNativeRuntime` → `UseEventHandlers` → `AddStandardLibrary`;
3. создаёт `HostedScriptEngine`, исходник с именем модуля «Песочница», затем `CreateProcess(host, source)` и `Start()`.

Перед `CreateProcess` вызывается `AttachBsp`: если код обращается к `ОбщегоНазначенияКлиентСервер.`, `ОбщегоНазначения.` или `СтроковыеФункцииКлиентСервер.`, нужные заглушки из `browser/bsp/*.bsl` (ресурсы сборки `bsp.<Модуль>`) компилируются и подключаются глобальными свойствами. Без обращения к ним ничего не компилируется: заглушки стоят ~40 мс нативно. Ошибка внутри заглушки выводится как «<Модуль> (заглушка БСП, строка N): …», без «Строка N:», чтобы не подсвечивать чужую строку в редакторе. `MachineInstance.SandboxMaxCallDepth = 3000` (правка 7).

`BrowserHost : IHostApplication`:
- `Echo` (`Сообщить`) пишет в список вывода;
- `InputString` (`ВвестиСтроку`) берёт строки из поля «Ввод»;
- `ShowExceptionInfo` выдаёт «Строка N: текст».

JSON собирается через `Utf8JsonWriter` вручную, потому что JSON через рефлексию в браузерной сборке отключён. Формат ответа: `{exitCode, ms, output: [{kind: "out"|"err", text}]}`.

Вывод `Консоль` перехватывается `OrderedConsoleWriter` и попадает в общий список в порядке вызовов вместе с `Сообщить`. Ошибки из-за неподдерживаемых в браузере API (`PlatformNotSupportedException`, например `HTTPСоединение`) показываются как «Эта возможность недоступна в браузере…».

### Проверка кода без запуска (`Runner.Check`)

`[JSExport] Check(code)` компилирует код, но не выполняет его, и возвращает `[{line, column, message}]`. В отличие от `Run`, в DI подменяется `IErrorSink` на `ListErrorSink`: компилятор не бросает исключение на первой ошибке, а собирает все. Включается `BslSyntaxWalker.SandboxCheckMode`, чтобы генератор кода не останавливался на испорченном операторе. Названия токенов вида `ClosePar` заменяются на символы (`Runner.Humanize`). Проверка занимает ~150–200 мс.

Во фронтенде (`app.js`):
- `@codemirror/lint`: проверка через 500 мс после остановки ввода, сообщение `{type: 'check'}` уходит в тот же воркер. Ошибки подчёркиваются, на полях ставится значок, текст виден при наведении. Ошибку без столбца (`column 0`) и «Ожидается ;» в начале оператора компилятор ставит на следующую лексему, поэтому они переносятся на конец предыдущей строки с кодом. Если проверка висит дольше 3 с, воркер перезапускается. «Ожидается ;» на строке, где уже есть другая ошибка, скрывается как её следствие. Незакрытая кавычка подчёркивается от кавычки до конца строки.
- Подсказки о совместимости (`RULES`) показываются ещё и жёлтыми предупреждениями на месте совпадения. Регулярные выражения используют `(?<![\p{L}\p{N}_])` вместо `\b`: в JS `\b` не работает с кириллицей.
- Ошибка выполнения («Строка N: …») подсвечивает строку и показывает текст в её конце (`runtimeErrorField`). Подсветка сдвигается вместе с текстом и снимается, как только меняется сама эта строка, а также перед новым запуском.

### Язык запросов (`browser/Query/`)

Класс `Запрос` выполняет подмножество языка запросов 1С над данными в памяти: таблицы значений из параметров (`ИЗ &Т КАК Т`), временные таблицы, вложенные запросы. Информационной базы нет. Регистрация: `env.AddAssembly(typeof(Runner).Assembly, t => t.Namespace == "OneScriptWasm.Query")` в `Runner.CreateEngine` (и для Run, и для Check). Правок OneScript не нужно.

- `QueryLexer.cs`: ключевые слова на русском и английском, регистр не важен, `//`, строки с `""`, `&Параметр`. Зарезервированы только структурные слова; `СУММА`, `Количество`, `Дата`, `Год` — обычные имена. После `КАК` допускается и служебное слово (`… КАК В`).
- `QueryParser.cs`: пакет (`;`), `ВЫБРАТЬ [РАЗРЕШЕННЫЕ] [РАЗЛИЧНЫЕ] [ПЕРВЫЕ N]`, `ПОМЕСТИТЬ`, `ИЗ` (параметр, временная таблица, `(ВЫБРАТЬ …) КАК Т`, запятая — декартово произведение), все `СОЕДИНЕНИЕ` (`ПО`/`ON`), `ГДЕ`, `СГРУППИРОВАТЬ ПО`, `ИМЕЮЩИЕ`, `ОБЪЕДИНИТЬ [ВСЕ]`, `УПОРЯДОЧИТЬ ПО`, `ИНДЕКСИРОВАТЬ ПО` и `ДЛЯ ИЗМЕНЕНИЯ` (принимаются и игнорируются), `УНИЧТОЖИТЬ`. Выражения: арифметика, `+` строк, сравнения, `И/ИЛИ/НЕ`, `В` (список, `&Массив`/`СписокЗначений`, подзапрос, в том числе коррелированный), `МЕЖДУ`, `ПОДОБНО` (`% _ [..] [^..]`, `СПЕЦСИМВОЛ`), `ЕСТЬ [НЕ] NULL`, `ВЫБОР КОГДА`, агрегаты, `ВЫРАЗИТЬ`, `ТИП()`, функции 8.3.20+ (`ДЛИНАСТРОКИ`, `СТРНАЙТИ`, `ЛЕВ`…, даты, `НАЧАЛОПЕРИОДА`, `РАЗНОСТЬДАТ`, математика). `ИТОГИ`, `ЗНАЧЕНИЕ()`, `ССЫЛКА`, `В ИЕРАРХИИ`, `ГРУППИРУЮЩИМ НАБОРАМ`, скалярный подзапрос — понятная ошибка. Для частых ошибок подсказки: `СТРДЛИНА` → `ДЛИНАСТРОКИ`, `%` → нет остатка от деления.
- `QueryExecutor.cs`: привязка полей (`Т.Поле`, `Поле` — «Неоднозначное поле», коррелированные подзапросы через `Scope.Parent`), источники, соединения (хеш по равенствам из `ПО`, остальное — вложенный цикл), `ГДЕ`, группировка (без `СГРУППИРОВАТЬ ПО` с агрегатами — одна группа даже на пустых данных), проверка «Поле не входит в группу», `РАЗЛИЧНЫЕ`, `ОБЪЕДИНИТЬ` (левоассоциативно), устойчивая сортировка, `ПЕРВЫЕ`. Предел 2 000 000 промежуточных строк. Подключаемые источники `IQueryTableProvider` (`QueryProviders.All`, сейчас пусто) — задел для демобазы `Справочник.Х`.
- `QueryValues.cs`: семантика значений запроса. Порядок типов NULL < Неопределено < Булево < Число < Дата < Строка < прочие; строки без учёта регистра и хвостовых пробелов (`CompareInfo` ru); NULL в сравнении → NULL (условие ложно), но в ключах группировки/`РАЗЛИЧНЫЕ`/`ОБЪЕДИНИТЬ` NULL равен NULL; в соединениях NULL ничего не соединяет; NULL при сортировке первым. Деление на 0 → NULL (как файловая база).
- `QueryFunctions.cs`: встроенные функции и `ВЫРАЗИТЬ` (значение другого типа → NULL, литерал заведомо другого типа — ошибка, `Число(N, M)` округляет половину от нуля).
- `QueryContexts.cs`: `Запрос` (`Текст`, `Параметры` — `Структура`, `МенеджерВременныхТаблиц`, `УстановитьПараметр`, `Выполнить`, `ВыполнитьПакет`, `ВыполнитьПакетСПромежуточнымиДанными`), `РезультатЗапроса` (`Выгрузить`, `Выбрать`, `Пустой`, `Колонки`), `ВыборкаИзРезультатаЗапроса` (`Следующий`, `Количество`, `Сбросить`, `НайтиСледующий`, `СледующийПоЗначениюПоля`, `Получить`, поля по имени и `["Поле"]`, `ЗаполнитьЗначенияСвойств`), `МенеджерВременныхТаблиц` (`Таблицы`, `Закрыть`), перечисление `ОбходРезультатаЗапроса`. Без менеджера временные таблицы живут один вызов `Выполнить`. `ПОМЕСТИТЬ` в `ВыполнитьПакет` даёт таблицу с колонкой `Количество`, `УНИЧТОЖИТЬ` — `Неопределено`. Колонки `Выгрузить()` типизируются по значениям (`Число, Null` и т. п.; с `Неопределено` или объектами — без типа, иначе Null превратился бы в 0).
- Ошибки — `RuntimeException` в формате платформы: `Ошибка при вызове метода контекста (Выполнить): {(2, 9)}: Поле не найдено "Т.Х"` и на следующей строке строка запроса с `<<?>>`. Позиция «Поле не найдено» — на последней части имени.
- Имена колонок: псевдоним; `Т.Товар` → `Товар`; агрегат, `ЕСТЬNULL`, `ВЫРАЗИТЬ` над полем → имя поля; прочее → `Поле1`, `Поле2`; повторы → `Товар1`.
- Отступление от платформы (сознательное): `ИЗ &ТЗ` разрешено в любом запросе и с нетипизированными колонками. В платформе — только в запросе с `ПОМЕСТИТЬ`, без соединений и объединений, с типизированными колонками. Проверка в редакторе показывает это жёлтым предупреждением; примеры написаны в совместимом стиле.
- `QueryChecker.cs` (проверка в редакторе): сканер строковых литералов BSL (повторяет `StringLexerState`: `|`, `""`, соседние литералы), литерал считается запросом, если начинается с `ВЫБРАТЬ/SELECT/УНИЧТОЖИТЬ/DROP` и стоит после `.Текст =`/`Новый Запрос(` либо многострочный с `ИЗ`; склейку через `+` не проверяем. Синтаксические ошибки — ошибки, `Справочник.Х` и `&ТЗ` без `ПОМЕСТИТЬ` — предупреждения. В JSON `Check` у таких элементов поля `length`, `severity: "warning"`, `source: "Запрос"`; `editor.js` их учитывает.
- Скорость: соединение 10 000 × 10 000 по ключу с группировкой — 41 мс нативно, 78 мс в браузере.
- Тесты: `python3 tests/run_query_tests.py <native.dll>` — `tests/query/*.os` против `.expected`, `*-check.os` против JSON проверки, плюс прогон всех примеров из `examples.js` (с их вводом). `--update` перезаписывает эталоны (только после ручной проверки вывода).

### Модули фронтенда (`page/src/`)

- `engine.js`: класс `Engine` (воркер, `run`, `check`, таймауты, перезапуск, `whenReady`). Его используют главная и виджет.
- `editor.js`: `createEditor` (CodeMirror, подсветка, линтер, подсветка ошибки выполнения, `gotoLine`).
- `rules.js`: подсказки о совместимости. Список функций-заглушек БСП берётся прямо из `browser/bsp/*.bsl` (esbuild `--loader:.bsl=text`), о них предупреждения нет.
- `output.js`: окно вывода. `share.js`: код в адресе. `examples.js`: примеры с `seoTitle`, `description`, `intro` для страниц примеров.
- Сборка: `app.js` и `embed-app.js` одним вызовом esbuild с `--splitting` (общий код в `chunks/`), `embed.js` отдельно как IIFE без модулей. Всё в `page/dist/`, оттуда копируется в `site/`.

### Ссылка «Поделиться» (`share.js`)

Формат: `#c=<код>&i=<ввод>`. Значение начинается с `z` (deflate-raw через `CompressionStream` + base64url) или `u` (UTF-8 + base64url без сжатия, если сжатие недоступно или длиннее). Распаковка ограничена 1 МБ. `#ex=<id>` открывает пример. Код после `#` на сервер не уходит.

На главной ссылка разбирается до создания редактора (top-level await, поэтому `--target=es2022`), загруженный код сразу сохраняется в черновик. Адрес с `#c=` остаётся, пока код и ввод совпадают с ним; после первой правки он убирается из адресной строки (`dropHashIfChanged`). Окно «Поделиться» (`<dialog>`): ссылка, код `<iframe>` для встраивания и код веб-компонента. При открытии ссылка копируется в буфер. Если ссылка длиннее 6000 символов, показывается предупреждение: форумы и мессенджеры такие обрезают.

### Виджет (`embed.html`, `embed-app.js`, `embed.js`)

- `embed.html#c=…&i=…&theme=light|dark&fit=1`: компактная панель («Запустить», статус, «Открыть в песочнице ↗», «Лицензии»), редактор, поле «Ввод» (только если есть ввод или `ВвестиСтроку`), вывод. `noindex`.
- Движок грузится лениво: при первом наведении, нажатии, фокусе или запуске. Статьи могут содержать несколько виджетов.
- Тема: параметр `theme`, иначе выбор пользователя на сайте (тот же `localStorage`, origin общий), иначе системная. Без параметра `theme` виджет слушает событие `storage` и перекрашивается, когда тему меняют на странице того же сайта.
- Ссылка «Лицензии» в панели виджета скрыта, если виджет стоит на странице самого 1Candbox (`window.parent.location.origin` совпадает, класс `on-own-site`): там она есть в подвале. На чужих сайтах ссылка остаётся: по MPL-2.0 читатель должен знать, где взять исходники OneScript.
- `fit=1`: высота по содержимому (редактор до 440 px, вывод до 260 px), виджет шлёт родителю `{type: 'bsl-sandbox:resize', height}`.
- `<bsl-sandbox>` (`embed.js`): код из `<script type="text/bsl">` или из текста элемента (`<pre><code>`), ввод из `<script type="text/bsl-input">` или атрибута `input`; общий отступ убирается. Shadow DOM с `<iframe loading="lazy">` на `embed.html` того же сайта, что и скрипт. Высоту подстраивает по сообщениям только от своего iframe. В коде внутри `<script>` последовательность `</script` пишется как `<\/script`.
- Хабр не пропускает сторонние скрипты и iframe, туда только ссылка.

### SEO (`page/build-pages.mjs`)

### Правки OneScript (`scripts/patch_onescript.py`, можно запускать повторно)

1. Из `ScriptEngine.HostedScript.csproj` убрана ссылка на `OneScript.Web.Server` (ASP.NET Core не собирается под WebAssembly).
2. В `OneScript.StandardLibrary/Text/ConsoleContext.cs` подписка `Console.CancelKeyPress` обёрнута в `try/catch (PlatformNotSupportedException)`. В браузере нет POSIX-сигналов: без этой правки падал любой запуск ещё на создании глобального объекта `Консоль`.
3. Сбор всех синтаксических ошибок для проверки. На запуск не влияет: там `ThrowingErrorSink` бросает исключение на первой ошибке.
   - `DefaultBslParser.BuildCodeBatch`: после «Ожидается ;» разбор продолжается, а не прерывается до конца модуля. Если следующий оператор начинается с имени, он не пропускается.
   - `NextStatementRecoveryStrategy`: восстановление останавливается и на `;`, а не только на `Если/Для/Пока/Попытка/Перем`.
   - `DefaultBslParser.AddError`: на `;`, `Тогда`, `Цикл` и закрывающем слове открытого блока ничего не пропускается, иначе пропуск идёт до закрывающих слов всех открытых блоков. Защита от зацикливания: вторая ошибка в той же точке всегда сдвигает разбор.
   - `BslSyntaxWalker.VisitCodeBlock`: в режиме `SandboxCheckMode` сбой генератора кода на одном операторе не мешает обойти остальные.
4. `StringLexerState`: ошибка незакрытой кавычки указывает на начало незакрытого фрагмента (открывающую `"` или `|` строки продолжения). Раньше она вставала на строку ниже, потому что возникала на символе перевода строки. Текст ошибки заменён на «Незакрытая кавычка в строковом литерале». Действует и при запуске.
5. `DefaultBslParser.NextLexem`: в режиме проверки ошибка лексера (незакрытая кавычка, недопустимый символ) записывается в `ErrorSink`, и разбор продолжается. Незакрытая строка считается литералом до конца строки, а прочие ошибки того же оператора не записываются (`_sandboxSuppressErrors` сбрасывается в начале каждого оператора в `BuildCodeBatch`).

6. `BslNumericValue.ToString`: представление числа как в платформе (ru): «2,5», «1 234 567» (группы через неразрывный пробел U+00A0), без хвостовых нулей («2,2», а не «2.20») и без экспоненты. Так числа выглядят в `Сообщить`, `Строка()`, при сложении со строкой и в `СтрШаблон`. `XMLСтрока` и JSON пишут «2.5», `Формат` работает как раньше.
   - 6а. `BslNumericValue.Parse`: `Число("2,5")` принимает запятую (если точки нет). Текст ошибки как в платформе: «Преобразование значения к типу Число не может быть выполнено» (было «(null) Преобразование к типу 'Число' не поддерживается»). `Число("1 000")` по-прежнему ошибка, как в платформе.
7. `MachineInstance.PushFrame`: предел глубины вызовов `SandboxMaxCallDepth` (Runner ставит 3000). Кадры стека OneScript лежат в куче, поэтому бесконечная рекурсия крутилась до таймаута 8 с. Теперь сразу ошибка «Переполнение стека встроенного языка: глубина вызовов превысила 3000…», её можно перехватить в `Попытка`. Рекурсия на 3000 вызовов в браузере занимает ~0,1 с.
8. `ScriptException.MessageWithoutCodeFragment` (это `ОписаниеОшибки()` и первая строка `ПодробноеПредставлениеОшибки`): формат платформы `{Песочница(3)}: текст` вместо `{Модуль Песочница / Ошибка в строке: 3 / текст}`.

Проверить, что скрипт применяется повторно: `python3 scripts/patch_onescript.py onescript` дважды подряд, во второй раз всё «уже применено». Новую правку, меняющую код из старой правки, вносить в текст старой правки, а не отдельным шагом поверх неё. Новый текст каждой правки должен быть уникальным, иначе она сочтётся «уже применённой». Проверка с чистых исходников: `git -C onescript checkout -- <файлы>`, затем скрипт.

## Лицензии (обязательно для публикации)

Сайт отдаёт браузеру сборки OneScript, и по MPL-2.0 это считается распространением. Поэтому на сайте должны быть текст MPL, исходники OneScript с нашими правками и уведомления о сторонних лицензиях. Всё это делает `scripts/collect_licenses.py`, его вызывает `build.sh` после сборки:
- `site/licenses/OneScript-MPL-2.0.txt`, `OneScript-source.txt` (репозиторий, коммит клона, список изменённых файлов), `patch_onescript.py`;
- `site/licenses/THIRD-PARTY-NOTICES.txt`: рантайм .NET (LICENSE и THIRD-PARTY-NOTICES из NuGet-кэша, в том числе ICU), NuGet-библиотеки, чьи `.wasm` попали в `_framework` (по `browser/obj/project.assets.json`), npm-пакеты из бандла (по метафайлу esbuild `page/meta.json`);
- `site/licenses.html` из шаблона `page/public/licenses.html`: подставляются таблица компонентов (`<!--COMPONENTS-->`) и коммит (`{{ONESCRIPT_*}}`).

Список собирается автоматически, поэтому новые зависимости попадут в него сами. Если у пакета нет файла лицензии, скрипт останавливает сборку. Текстовые файлы пишутся с BOM (`utf-8-sig`): статические серверы отдают `.txt` без charset, и без BOM кириллица превращается в кракозябры. В подвале главной страницы есть оговорка «Сайт не связан с фирмой «1С»» и ссылка на `licenses.html`.

Товарный знак: «1С» принадлежит фирме 1С. Для платного сервиса лучше не делать «1С» главным словом бренда и не использовать её логотипы. Задачи придумывать самим, не копировать из Stepik, 1Craft и других тренажёров.

## Публикация (`deploy/`)

Свой VPS с Ubuntu 22.04/24.04 и Caddy. Сайт собирается на Mac, на сервер копируется только `site/`.
- `deploy/server-setup.sh ДОМЕН` (от root, один раз, повторный запуск безопасен): обновления и `unattended-upgrades`, Caddy из официального репозитория (cloudsmith), пользователь `deploy` без sudo (ключи от root), `/var/www/1candbox/releases`, вход по SSH только по ключу (`/etc/ssh/sshd_config.d/10-1candbox.conf`, только если у root есть ключ), `ufw` (SSH, 80, 443/tcp+udp), Caddyfile с подставленным доменом и `caddy validate`.
- `deploy/Caddyfile` (`__DOMAIN__`): `file_server { precompressed br gzip }` для готовых `.br`/`.gz` из `_framework`, `encode zstd gzip` для остального, `Cache-Control: no-cache` (имена файлов без хэшей — браузер перепроверяет и получает 304), своя 404 через `handle_errors` + `expression {err.status_code} == 404` (работает и на старых Caddy без `handle_errors 404`), `www` → без `www`, лог с ротацией. `X-Frame-Options`/`frame-ancestors` не ставить: виджет встраивают на чужие сайты.
- `deploy/deploy.sh` (настройки в `deploy/deploy.env`, он в `.gitignore`; образец `deploy.env.example`): `SITE_URL=… ./build.sh` → `rsync -rlcz --link-dest=current` в `releases/<дата-время>` → `chmod -R go+rX` → симлинк `current` через `ln -sfn` + `mv -T` → хранить последние `KEEP=5`. `-c` без `-t`: неизменённые файлы становятся жёсткими ссылками на прошлый релиз с прежней датой, ETag в Caddy (дата+размер) не меняется, кэш `_framework` у посетителей сохраняется. `--chmod` не используется: системный openrsync в macOS его не знает. Перед выкладкой проверяет, что `site/sitemap.xml` собран с тем же `SITE_URL`. `--no-build`, `--rollback`.
- Не проверено на настоящем сервере: `server-setup.sh` и Caddyfile проверены только на синтаксис (`bash -n`), `caddy validate` выполняется при настройке. rsync с `--link-dest` проверен локально.

## Известные отличия и риски

- Числа выводятся как в платформе, в том числе с неразрывным пробелом между разрядами: `Число(Строка(1000))` даёт ошибку, как и в платформе.
- `ОписаниеОшибки()`: `{Песочница(3)}: текст`. В платформе вместо «Песочница» полное имя модуля (`ОбщийМодуль.Имя.Модуль`).
- Заглушки БСП написаны с нуля по описанию функций и повторяют только основное поведение. Ошибка внутри заглушки показывает строку заглушки, а не строку вызова в коде пользователя.
- В браузере могут найтись другие места OneScript, которые зовут неподдерживаемые API (процессы, файлы, сеть, часовые пояса). Ловить по `PlatformNotSupportedException` и патчить точечно, как с `Консоль`.
- Размер `_framework`: десятки мегабайт (рантайм, сборки, ICU). Кэшируется браузером, но первую загрузку стоит уменьшить.
- Mono-интерпретатор в WebAssembly медленнее нативного .NET. Для учебных алгоритмов это незаметно.
- Безопасность: код пользователя заперт в песочнице браузера, от зависаний защищает таймаут 8 с с пересозданием воркера.
- Запросы: нет информационной базы (справочники, документы, регистры, `ЗНАЧЕНИЕ()`, разыменование `Т.Ссылка.Поле`), `ИТОГИ`, `ГРУППИРУЮЩИМ НАБОРАМ`, многоколоночного `(А, Б) В (…)` и вложенной формы соединений. Таблица значений из параметра разрешена в любом запросе (платформа требует `ПОМЕСТИТЬ` и типизированные колонки). `СРЕДНЕЕ` и деление дают до 28 знаков `decimal`, платформа гарантирует от 8. Тексты ошибок уровня LOW из спецификации (уже существующая временная таблица, разное число полей в `ОБЪЕДИНИТЬ`) не сверены с живой платформой.
- Глубина вызовов ограничена 3000. Реальный предел платформы зависит от размера стека и может отличаться.
- Цикл на 1 000 000 итераций идёт ~2,2 с: интерпретатор Mono в WebAssembly медленный.
- Проверка кода: после пропущенной `;`, за которой идёт не имя, следующий оператор пропускается и не проверяется. Неизвестные символы внутри оператора с синтаксической ошибкой (например, в теле `Если` без условия) не находятся. Ошибки выполнения (индекс, деление на ноль, типы) до запуска не видны.
